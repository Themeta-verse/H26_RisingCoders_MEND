The **MEND Frontend** is a responsive, high-density web dashboard built with **React 18**, **TypeScript**, and **Vite**. It adheres to a technical Swiss Editorial aesthetic, combining dark charcoal surfaces, electric cobalt accents, crisp monospace data tables, and intuitive status badges for audit-ready dependency intelligence.

---

## Key Features & UI Sections

### 1. Top Navigation & Global Controls
- **Repository Selector**: Instantly switch between the pristine `LinkWatch` benchmark and any cloned public GitHub repository. Displays active repository name, 10-character commit SHA, and revision status (`Benchmark: Immutable` vs `Revision: Fetched`).
- **Add Repository Modal**: Input any public GitHub repository URL (e.g., `https://github.com/bottlepy/bottle`) to shallow-clone and register new targets without executing untrusted code.
- **Repository Operations**:
  - **Re-scan**: Re-executes static AST and manifest parsing on current local files without making remote network calls.
  - **Sync with GitHub**: Fetches the latest remote revision from origin for cloned repositories (explicitly protected against modifying the immutable LinkWatch benchmark).
  - **Drift Check**: Computes an in-memory snapshot diff comparing the previous scan with the current scan to view added/removed dependencies and specifier shifts.
- **System Status Bar**: Live indicator showing Ollama daemon health (`http://localhost:11434`), configured model tag (`gemma4:e2b-it-q4_K_M`), and detected ecosystem support level (`FULL`, `PARTIAL`, or `UNSUPPORTED`).
- **Theme Toggle**: Switch seamlessly between Technical Dark Mode and Crisp Light Mode.

### 2. Six Navigation Tabs

#### Tab 1: Dependency Inventory
- **Interactive Search & Filtering**: Filter dependencies by name, or view quick subsets: All dependencies, Manifest Conflicts, or Direct AST Usages.
- **Side-by-Side Dependency Intelligence Matrix**: Directly compares declared versions, installed runtime versions, verified latest stable releases from PyPI, and recommended migration targets.
- **Official Documentation Links**: Direct clickable links to PyPI project pages, official release notes, documentation, changelogs, and source repositories.
- **AST Code Usage Explorer**: Expandable inspect views showing exact file paths, line numbers, and imported symbols for every dependency.

#### Tab 2: Rule Engine Findings
- Displays detections from 8 deterministic static resilience rules (e.g., transitive incompatibility, manifest version conflict, abandoned libraries, deprecated runtime APIs, phantom packages).
- Each finding includes severity tags (`CRITICAL`, `WARNING`, `INFO`), rule identifier, affected package, rationale, and exact code context snippets with file paths and line numbers.

#### Tab 3: Gemma 4 Advisory
- AI-assisted migration plans generated by local **Gemma 4** (`gemma4:e2b-it-q4_K_M`) via Ollama.
- Features:
  - **Live Elapsed Timer**: Visual timer `(Xs elapsed)` indicating request duration.
  - **Cancellation Button**: Aborts pending model requests immediately without locking the interface.
  - **Structured Advice Cards**: Categorized by migration type (`version_bump`, `library_replacement`, `code_migration`, `informational_stdlib`), step-by-step migration procedures, proposed code diffs, suggested validation test commands, and unresolved risks.

#### Tab 4: Sandbox Verification
- **Baseline Test Execution**: Runs `pytest` in the target virtual environment in read-only mode to capture baseline status (e.g., LinkWatch: 9 Passed, 1 Failed).
- **Isolated Candidate Execution**: Tests candidate dependency upgrades in temporary sandbox directory clones using prioritized `PYTHONPATH` overrides.
- **Side-by-Side Comparison**: Contrasts baseline vs. candidate pass/fail counts, execution duration, and exit codes.
- **Deterministic Verdict Badges**: Highlights empirical verdicts (`VERIFIED_FIX`, `STILL_FAILING`, `REGRESSION`, `INCONCLUSIVE`, `BLOCKED`).
- **Expandable Test Logs**: Full stdout and stderr terminal logs with raw failure tracebacks.

#### Tab 5: Migration Integrity Ledger
- Visual state machine tracking every dependency across strict lifecycle stages:
  `OBSERVED ──▶ RECOMMENDED ──▶ EXECUTED ──▶ VERIFIED / FAILED / INCONCLUSIVE`
- Displays individual SHA-256 entry fingerprints bound to repository identity and commit SHA.

#### Tab 6: Exit Capsule Export
- Download machine-readable **Dependency Exit Capsule JSON** (schema `1.0.0`).
- Download and preview the **Standalone Zero-Dependency HTML Report**.
- Displays the **Manifest Snapshot SHA-256** digest and payload SHA-256 digest for CI/CD compliance audits.

## Local Development & Build

### Prerequisites
- Node.js 18+ (tested with Node.js v24.19)
- npm 9+

### Commands

```bash
# Navigate to the frontend directory
cd mend/frontend

# Install dependencies
npm install

# Start Vite development server with hot-module reloading
npm run dev
# Server starts at http://localhost:5173 (proxies /api to http://127.0.0.1:8000)

# Build production bundle
npm run build
# Outputs optimized static assets to mend/frontend/dist/
```

> **FastAPI Integration**: When built, the FastAPI backend automatically serves `mend/frontend/dist/` at `http://127.0.0.1:8000/`, allowing single-command startup of the complete full-stack workbench.
